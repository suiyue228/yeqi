# 「夜栖 · 月下树洞」项目总执行文档（统一版本）

请将本文件视为当前项目的统一执行总任务书。  
本次任务的目标不是简单补几个功能，而是对当前项目进行一次以“氛围、视觉完成度、交互仪式感、结构完整性”为核心的系统升级。

## 一、执行总原则（最高优先级）

### 1. 画面效果优先级较高
本项目是一个具有明显审美导向的网页作品，画面效果、氛围完整度、视觉统一性和表现力的优先级很高。

请遵守以下原则：

- 不要为了增加功能数量而牺牲画面质量。
- 如果时间、结构或实现难度有限，可以少做一些功能，但必须保证已经做出来的页面、场景、组件和交互具有较高完成度。
- 不要堆出很多粗糙、简陋、像占位稿一样的页面。
- 与其做 10 个空壳功能，不如做 4～6 个真正完整、好看、可用、风格统一的模块。
- 不要用普通后台卡片、常见 AI hero 模板、大量相似矩形盒子来糊弄画面。
- 不要只用一些简单线条和小图标假装“哥特”。
- 不要让复杂功能压垮美术表现；必要时可以牺牲部分功能广度，优先保证视觉质量和沉浸感。

### 2. 保留当前项目成果，不推翻重做
本次工作应以当前项目为基础继续迭代，不要无必要推翻已有可用实现。

### 3. 分阶段执行，自动记录
本次任务必须按阶段执行。  
每完成一个阶段，都必须：

1. 进行阶段性自检。
2. 更新进度记录。
3. 记录已完成内容、未完成内容、测试结果和下一步计划。
4. 在 Git 状态适合的情况下建立阶段性检查点。

除非遇到明确阻碍，否则请继续推进到下一阶段，不要每做完一点就停下来等待我再次布置任务。

### 4. 如无法确认，不要编造
如果某项资源、页面状态、音频素材、运行环境或浏览器预览无法确认，请如实说明，不要假装已经验证。

## 二、项目背景与整体定位

项目名称暂定：夜栖 · 月下树洞（Moonlit Treehole）

这是一个具有暗黑哥特童话、梦境绘本、神秘剧场、私人记忆收纳气质的树洞网站。  
用户可以记录自己的心情、琐事、烦恼、回忆和愿望。

它不应当是普通的信息管理页面，而应当像一个可以进入、可以停留、可以慢下来、可以反复回望记忆的神秘空间。

本项目的关键词：

- 暗黑哥特
- 梦境绘本
- 神秘剧场
- 纸艺舞台
- 私人树洞
- 月亮、星星、档案、信笺、帷幕、抽屉、纸雕、旧日记、秘密花纹

## 四、风格与视觉方向

### 1. 视觉总风格
请继续保持并强化以下风格：

- 暗黑哥特童话感
- 梦境绘本感
- 插画式页面
- 旧式剧院 / 神秘舞台感
- 精致、优雅、略带忧郁
- 具有装饰性但不杂乱
- 具有手工作品、纸艺、物件收藏感

### 2. 画面构成原则
- 页面必须有主视觉重心。
- 页面必须有次级视觉区域。
- 装饰元素要服务于构图，而不是平均铺满整个页面。
- 保持“丰富但不杂乱”。
- 每个页面尽量拥有 1 个主视觉焦点和 2～3 个次级视觉组。
- 优先补强大轮廓场景元素、结构性装饰与场景氛围，再补小型符号。

### 3. 禁止事项
- 不要使用普通 hero + 三列卡片 + 顶部导航的常见 AI 网页布局。
- 不要堆积大量相同样式的圆角卡片。
- 不要用科技风、SaaS 风、玻璃拟态、电商风替代当前风格。
- 不要为了显得复杂而无意义堆料。
- 不要做出很多一眼看上去像占位稿的“假装功能页”。

## 五、必须解决的核心问题

### 1. 幕布切换太快
当前开合幕布速度偏快，这不符合“慢下来记录”的主题，显得太急躁。

必须修改：
- 幕布开合速度明显放慢。
- 切换节奏更从容、更有仪式感。
- 开合过程中应给用户“进入空间”“拉开舞台”“缓慢展开秘密”的感觉。
- 不能是快速机械滑开。

同时必须兼顾：
- 速度变慢后仍然流畅，不拖沓。
- 不影响基本操作。
- 兼容 reduced-motion。

### 2. 小剧场要更有表现力与可交互性
立体纸艺小剧场不仅要好看，还必须有一定可交互性。

新增要求：
- 顶部加入下垂的星星和月亮。
- 星星和月亮通过一根线悬挂，看起来像真实的手工作品 / 手工纸艺装置。
- 鼠标滑过星星时，星星会摇摆。
- 星星摇摆时发出类似风铃的空灵声音。
- 交互需要自然、优雅，不要粗糙。
- 不要只是装饰图层，必须有一定互动反馈与舞台感。

### 3. 功能路径过度集中
当前很多功能最后都会回到写信笺，这会导致网站结构单一。

必须解决：
- 让各个功能模块成为独立存在的区域。
- 让用户有“记录、回看、整理、回响、收藏、体验”的完整路径，而不是所有入口都只是通往写信。

# 阶段 1：幕布切换升级（视觉 + 节奏）

## 目标
把当前幕布切换升级为更精致、更繁复、更具有舞台感和仪式感的哥特帷幕，并且显著放慢开合速度，使其符合“慢下来记录”的主题。

## 重点要求

### A. 视觉升级
幕布应加入更繁复、精致的装饰，例如：
- 哥特植物纹样
- 对称藤蔓
- 荆棘与玫瑰
- 蕾丝边
- 刺绣感花纹
- 月相、星象、纹章
- 流苏、吊坠、装饰帘幔
- 层叠布料结构
- 旧剧院、神秘舞台感

### B. 动作升级
必须解决“幕布开合太快”的问题：

- 开合速度应明显比当前更慢
- 节奏更柔和、更从容
- 应有“慢慢拉开”“缓缓合拢”的感觉
- 布料、边缘装饰、前后层帘可有轻微层次差
- 不要拖成沉重卡顿，也不要快得急躁
- 用户在切换时应感受到“停顿、进入、沉浸”

### C. 技术与体验
- 不要造成闪屏
- 不要提前露出内容
- 不要让装饰错位
- 兼容 reduced-motion
- 保持可维护性

# 阶段 5：立体纸艺小剧场（重点阶段）

## 目标
制作一个高完成度、具有暗黑哥特纸艺立体感的小剧场模块，使其成为整个网站最有记忆点的特色模块之一。

## 总体要求
小剧场不仅要好看，还要有一定可交互性。  
它不能只是背景装饰，而应像一个可以轻微探索、可以触发内容、可以停留观看的纸艺舞台空间。

## 视觉要求
- 立体纸艺 / 纸雕剧场风格
- 明确的前景、中景、后景
- 纸片厚度、切边、叠层感
- 暗黑哥特童话氛围
- 与全站风格统一
- 不要像普通网页插画拼贴

## 场景建议
可优先实现一个主场景，例如：
- 月下秘密剧院
- 哥特窗前的纸艺舞台
- 树洞深处的纸雕小剧场

## 必须加入的新要求

### A. 顶端悬挂元素
小剧场顶部加入：
- 通过一根线悬挂下来的星星
- 通过一根线悬挂下来的月亮
- 看起来像真实手工装置 / 手工挂件 / 手工作品的一部分

### B. 悬挂元素交互
- 鼠标滑过星星时，星星要有相应摇摆
- 摇摆动作应自然，不要过度夸张
- 星星摇摆时发出类似风铃的空灵声音
- 声音必须轻柔、克制、精致
- 不要每次轻微移动都过度触发
- 悬挂元素要真正融入场景，而不是单独漂浮 UI

### C. 小剧场的可交互性
除顶部星星外，小剧场本身至少还要具备若干真实互动点，例如：
- 点击纸艺角色触发一句对白或片段
- 点击纸艺门、抽屉、书本或道具触发展开
- 通过一个机关进入某条记忆或某个模块
- 有明确反馈，不是点了没反应

### D. 纸艺人物
建议至少实现一名具有辨识度的原创纸艺风暗黑哥特角色。  
角色不要求复杂骨骼动画，但需要有一定视觉完成度和轻微动态表现。

## 本阶段优先原则
如果小剧场的功能与其他一般功能发生资源冲突，优先保证：
- 场景质量
- 纸艺立体感
- 顶部悬挂星月效果
- 基础互动质量

不要为了多做机关而牺牲整体画面。

## 本阶段记录要求
在 PROGRESS.md 中记录：
- 小剧场场景是什么
- 做了哪些分层
- 实现了哪些交互

- 影响画面完成度的问题
- 影响沉浸感的问题
