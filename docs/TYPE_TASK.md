# 「夜栖 · 月下树洞」字体系统与艺术字专项升级

请在当前已经完成开发的「夜栖 · 月下树洞」项目基础上，对全站字体、文字排版和部分重要标题的艺术字进行一次系统性的视觉升级。

当前问题：

1. 界面字体太普通、太僵硬，缺少艺术设计感。
2. 字体与网站暗黑哥特童话、梦境绘本、神秘剧场的视觉风格不够协调。
3. 写信笺时的字体过于生硬，缺少温柔、自然的手写质感。
4. 一些重要标题只是普通文字，缺乏作为视觉元素的表现力。

本次任务以提升文字美术质量为核心，不需要重新开发网站功能，也不要无必要地改变现有布局、插画、场景和交互。

## 一、最高优先级：建立具有层次的字体设计系统

请不要简单地为整个网站替换成同一种字体。

应当根据不同文字的用途，建立一套风格统一、但层次分明的字体系统。

### 1. 一级标题：哥特童话艺术字体

适用位置：

- 网站主标题「夜栖 · 月下树洞」。
- 首页重要章节标题。
- 记忆档案馆标题。
- 心情月历标题。
- 小剧场标题。
- 其他具有场景意义的大型标题。

风格要求：

- 神秘、精致、优雅。
- 具有复古绘本、哥特童话、旧式剧院的艺术气质。
- 可以参考古典书籍封面、装饰性字体、手绘招牌与复古印刷字的设计语言。
- 适度使用细长笔画、装饰性曲线、独特的文字结构。
- 保持清晰的字形和良好的视觉平衡。
- 不要使用僵硬的默认黑体作为主要展示效果。
- 不要把所有标题都做成一模一样的字体和装饰。

特别注意中文字体的实际效果。不要直接把英文哥特字体套用到中文上，导致中文仍然显示为普通系统字体。

### 2. 二级标题与功能入口字体

适用位置：

- 写信笺。
- 打开档案。
- 进入小剧场。
- 心愿瓶。
- 今夜回响。
- 草稿匣。
- 各类导航入口与功能区标题。

希望这些文字带有一定手绘气质和古典装饰感。

可以采用：

- 稍微圆润或灵动的字形。
- 具有书写感的笔画。
- 轻微的字距变化。
- 精致的装饰线、星月符号和花纹。
- 类似神秘绘本目录的字体设计。

但不要影响识别和操作。

### 3. 普通界面字体

适用位置：

- 功能说明。
- 按钮。
- 日期。
- 搜索与筛选。
- 设置。
- 提示信息。
- 普通正文。

这些文字不需要过度艺术化。

请选择与整体风格协调、略带柔和或复古气质的字体，保持自然、易读。

不要将所有普通文字都替换成复杂的书法或装饰字体。

## 二、重要标题可以单独设计艺术字

我希望一些重要标题不只是普通字体，而是像网页插画本身的一部分。

请选择少量真正具有视觉地位的标题进行专属艺术字设计。

优先考虑：

1. 「夜栖 · 月下树洞」
2. 「记忆档案馆」
3. 「月下小剧场」
4. 「写给今夜的信」
5. 「今夜回响」

不要求全部制作成独立艺术字，应优先保证主标题及最重要场景标题的质量。

### 艺术字设计方向

可以使用：

- 哥特植物纹样。
- 细小玫瑰与荆棘。
- 星星与新月。
- 细长的装饰曲线。
- 手绘花体结构。
- 不规则的字形组合。
- 旧书封面式排版。
- 少量装饰性首字或尾字。
- 类似印刷版画的轮廓与细节。

艺术字应自然融入现有画面，像经过专门设计的插画标题，而不是普通文字周围随便摆几颗星星。

### 实现方式

优先考虑：

- 高质量的实际字体。
- 可维护的 SVG 装饰。
- 基于真实文字构建的组合式标题。
- 必要时制作独立的原创矢量标题资产。

如果需要独立生成艺术字图像，应确保中文字形、笔画、文字内容准确，不允许出现 AI 生图常见的错字、伪文字、文字变形或笔画错误。

不要只是用 text-shadow、渐变和描边叠加来假装字体已经艺术化。

艺术字的底层应尽可能保留真实文本或可访问的文字替代，不能因为视觉装饰导致搜索、阅读和无障碍功能受损。

## 三、重点修改：写信笺时的手写字体

这是本次任务中非常重要的部分。

当前写信笺时使用的字体比较僵硬，缺少书写日记的温柔感。

我希望修改为：

**圆润、可爱、自然、清秀、略带稚拙感，但不幼稚的中文手写体。**

### 1. 字体气质

希望给人以下感觉：

- 像用圆润笔尖写在日记本上的字。
- 有柔和自然的笔画。
- 字体不过于方正、刻板。
- 有适度的手写不规则感。
- 字形饱满、亲切。
- 带一点童话绘本的可爱感。
- 适合安静、放松地写日记。

请注意：

我想要的是温柔自然的手写体，而不是难以辨认的狂草、过分夸张的儿童涂鸦字或刻意卖萌的卡通字体。

### 2. 使用范围

至少需要统一调整：

- 写信笺时的正文输入区域。
- 信笺标题输入区域。
- 输入框占位提示文字。
- 已保存信笺的详情阅读区域。
- 信笺预览中相应的正文文字。

其中正文的字体优先级最高。

保证用户输入时和保存后阅读时，文字风格保持一致，不要出现编辑时是手写体，打开后却突然变回普通黑体的情况。

### 3. 排版要求

除了字体本身，请一起优化写信的阅读与输入体验：

- 设置舒适的字号。
- 适当增加行间距。
- 调整段落间距。
- 保证文字与信纸背景之间的对比度。
- 控制每行文字长度。
- 中英文、数字、标点混排时保持协调。
- 长篇书写时仍然清晰易读。
- 移动端不出现字体过小、文字重叠或输入异常。

我希望写信过程像在一本精美的手写日记中记录文字。

请不要使用过大的文字，也不要让整个信笺显得像儿童练字本。

如果合适，可以细微调整纸张颜色、行距或文本边距，但不要大规模改变现有信笺布局和装饰结构。

## 四、字体选择与资源要求

请优先寻找或检查真正适合中文显示的字体，而不是只考虑英文字体。

可以考察以下风格方向：

- 圆润自然的中文手写体。
- 柔和的手绘字体。
- 具有古典气质的中文宋体或装饰字体。
- 复古书籍标题字体。
- 与中文协调的英文古典衬线字体。

选用字体时，必须考虑：

1. 简体中文常用字覆盖情况。
2. 标点、数字和英文混排效果。
3. 字体的真实视觉质量。
4. 是否具有明确的合法使用许可。
5. 是否允许网页嵌入与随项目分发。
6. 字体文件体积及加载性能。
7. Windows 和常见移动浏览器上的表现。

请不要只根据字体名称判断好不好看。

优先筛选 2～3 套适合项目的字体组合，根据实际页面效果比较，并选择最协调的一套。

如果能够进行浏览器预览，请通过真实页面检查视觉表现。

### 特别要求

- 不要使用来源不明的商业字体。
- 不要擅自下载或嵌入许可不明确的字体文件。
- 不要因为字体过大而明显影响网站加载速度。
- 可根据实际需要使用 WOFF2、字体子集或本地字体回退方案。
- 不要错误地把只支持英文字母的字体当成完整的中文字体。
- 注意中文字体文件通常较大，优化不能以丢失常用汉字为代价。
- 如果需要在项目中包含字体文件，按其实际许可保存必要的许可证及署名信息。
- 如使用外部字体服务，应考虑加载失败时的回退表现和用户隐私。

## 五、全站字体层级与统一管理

请将最终采用的字体整理为清晰的字体体系。

例如：

- Display：重要场景标题及大型艺术字。
- Heading：普通章节标题和功能入口。
- UI：按钮、标签、说明与导航。
- Handwriting：信笺输入、正文及阅读。
- Accent：日期、档案编号、印章等少量装饰信息。

尽量通过 CSS 变量、字体类或主题系统进行统一管理。

不要在大量组件中分别硬编码字体名称。

艺术字资产应集中管理，方便以后继续扩展其他标题。

## 六、文字与整体画面的协调

本次修改必须继续符合当前项目的暗黑哥特童话风格。

特别注意以下场景：

### 首页

主标题要成为页面的一部分，具有更强的艺术感和视觉辨识度。

### 写信笺页面

文字柔和、可爱、舒适，呈现温暖的私人日记氛围。

### 记忆档案馆

标题可以偏复古、装饰性，记录列表正文需要清晰易读。

### 心情月历

日期、星期和情绪标识要精致，但不能因为更换字体降低信息辨识度。

### 立体纸艺小剧场

标题、人物对白和场景标签可以拥有手绘童话风格，像写在纸艺道具上的字。

不要让不同页面出现毫无关联的字体风格。

## 七、执行步骤

请自行按照以下阶段执行，无需每完成一小步就等待我重新下达任务。

### 阶段 1：现状检查

检查当前全站字体使用方式、现有字体资源、样式文件和相关组件。

确认哪些界面文字存在僵硬问题，哪些地方需要重点优化。

检查当前 Git 状态和项目规则。

### 阶段 2：字体筛选与设计

筛选适合中文的字体组合，并检查合法使用条件、加载体积及字形覆盖。

确定：

- 艺术标题字体。
- 普通界面字体。
- 信笺手写字体。
- 少量装饰字体。

如果实际字体选择无法达到高质量效果，应主动调整方案，不要机械完成替换。

### 阶段 3：信笺字体优化

优先完成信笺正文、标题、输入框、预览和阅读区域。

检查实际输入、保存与再次打开后的字体一致性。

完成后记录结果。

### 阶段 4：界面字体与艺术字升级

统一调整全站文字层级。

为少量重要标题制作具有辨识度的艺术字或装饰性标题组合。

重点提升首页、档案馆、小剧场等重要场景的文字表现。

完成后记录结果。

### 阶段 5：视觉检查和性能优化

检查：

- 字体是否真正加载成功。
- 简体中文是否显示正确。
- 标点与英文是否协调。
- 艺术字是否存在错字、错位。
- 不同屏幕尺寸下是否溢出或遮挡。
- 页面切换是否造成明显的字体闪烁或布局跳动。
- 写信输入是否正常。
- 字体文件是否造成不合理的加载负担。
- 是否影响原有网页功能。

如果可以使用浏览器预览，请实际检查桌面端与移动端。

### 阶段 6：文档和 Git

根据实际变更更新：

- docs/DESIGN_SPEC.md
- PROGRESS.md
- README.md（新增字体资源、授权或使用方式时）

如果需要补充长期字体规范，可以适度更新 AGENTS.md，但不要让其变得过于冗长。

检查 Git 差异，在完成必要验证、状态安全的情况下创建阶段性提交。

## 八、验收标准

本次修改完成后，应满足：

1. 全站主要标题明显更有艺术设计感。
2. 重要标题不再只是普通字体加简单装饰。
3. 写信笺正文具有自然、圆润、可爱的手写质感。
4. 写信与阅读字体协调统一。
5. 不同功能区域形成清晰的字体层级。
6. 整体保持暗黑哥特童话、神秘绘本的视觉方向。
7. 中文字符、标点和数字显示正确。
8. 保持良好的可读性与响应式表现。
9. 不破坏已有核心功能。
10. 字体资源合法、加载合理、易于长期维护。

如果美术效果与实现难度发生冲突，请优先提升主要展示标题和信笺书写区域的视觉质量，而不是平均修改全部文字。

宁可少做几个独立艺术字，也不要制作大量简陋、重复或缺乏设计感的文字装饰。
